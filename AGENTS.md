# AGENTS.md

Notes for coding agents (Codex, Claude Code and others) working on this repo:
the personal site of Yazan Boshmaf at https://yazan.boshmaf.com. Read this
before editing. `README.md` covers the same ground for people.

## What this is

- A static Jekyll 4.4 site. There is no backend, database or server code,
  and there must not be: it is hosted on GitHub Pages.
- Pushing to `main` deploys it (`.github/workflows/pages.yml`). There is no
  staging environment, so a push to `main` goes live within about a minute.
- The domain `yazan.boshmaf.com` (file `CNAME`) runs through Cloudflare, which
  adds analytics and three rules (see "Cloudflare" below).

## Layout

| Path | What it is |
| --- | --- |
| `_config.yml` | Site title, author details, contact info, social links, nav menu, `home_news` (how many news months the homepage shows) |
| `_data/pubs.yml` | Every publication, newest first. Source of truth for the publications page, homepage selection, search, `pubs.json`, structured data and WebMCP |
| `_data/news.yml` | News entries, newest first, grouped by month. Source for the homepage "Now" list, news page, Atom feed, search and `news.json` |

| `research.html` | Research statement. Prose, its table of contents and its numbered reference list are all hand-written here |
| `pubs.html`, `news.html`, `students.html`, `404.html` | The other pages |
| `_layouts/default.html`, `_layouts/page.html` | Page shells. `page` reads `eyebrow`, `heading`, `lede`, `updated` and `prose` from front matter |
| `_includes/` | `head.html` (meta, security policy, scripts, homepage Person data), `nav.html`, `footer.html`, `pub.html` (one paper), `news-item.html`, `search.html` |
| `assets/css/site.css` | All styles. Colours and fonts are CSS custom properties on `:root`, redefined for dark mode |
| `assets/js/theme.js` | Sets light/dark before first paint |
| `assets/js/site.js` | Theme toggle, contact details, publication filters, BibTeX copy, table-of-contents highlight, search palette |
| `assets/js/graph.js` | The animated agent graph in the homepage hero (canvas) |
| `assets/js/webmcp.js` | Read-only WebMCP tools for browser AI agents |
| `search.json`, `feed.xml` | Search index and Atom feed, generated by Liquid |
| `llms.txt`, `pubs.json`, `news.json`, `robots.txt` | Agent-facing files, generated by Liquid (see below) |
| `_scripts/agent_markdown.py` | Writes Markdown versions of pages after the Jekyll build (deploy only) |
| `img/`, `docs/boshmaf_cv.pdf`, `favicon.ico` | Images, CV, favicons |

Folders starting with `_` are not published. Root files without front matter
are copied as-is, so add any new non-site file (like this one) to `exclude` in
`_config.yml`.

## Data formats

`_data/pubs.yml`, one entry per paper, newest first:

```yaml
- title: "Paper title"
  authors: "First Author, Yazan Boshmaf, and Last Author"   # commas, then ", and" before the last
  year: 2026
  month: 9                     # 1-12, required
  kind: conference             # conference | journal | workshop | preprint
  short: "RAID ’26"            # badge text
  venue: "Proc. of ..."        # full venue name
  ref: "RAID ’26, Lancaster, UK, Oct 2026"
  url: "https://doi.org/..."   # prefer a DOI or arXiv link
  topics: [eval, ai]           # ai, eval, agents, chain, web, systems, mobile
  award: "Best paper award"    # optional
  selected: true               # optional: also show on the homepage
```

- Keep the `authors` format. The structured data on the publications page
  splits it on commas and "and" to list each author, and matches the exact
  string `Yazan Boshmaf` (from `site.author.name`) to link the paper to the
  homepage's Person data. A trailing `et al.` is allowed.
- `kind` sets the BibTeX type: `journal` and `preprint` become `@article`,
  the rest `@inproceedings`.
- A new topic must be added in three places: the entry's `topics`, a filter
  button in `pubs.html`, and `TOPICS` in `assets/js/webmcp.js`.

`_data/news.yml`, one entry per month, newest first:

```yaml
- date: 2026-10                # YYYY-MM
  award: true                  # optional: highlights the entry
  items:
    - "Markdown text, with [links](https://example.com)."
```

## Build, preview and checks

- Requires Ruby 3.3+ and Bundler. `README.md` has per-OS install notes.
- `bundle install`, then `bundle exec jekyll serve --livereload` and open
  http://localhost:4000. Restart after changing `_config.yml`.
- `bundle exec jekyll build` writes `_site/`. The Markdown versions are not
  built by Jekyll; to produce them locally run
  `pip install -r _scripts/requirements.txt` then
  `python _scripts/agent_markdown.py _site`.
- There are no automated tests. Before pushing, check that:
  - `bundle exec jekyll build` finishes without errors;
  - `python _scripts/agent_markdown.py _site` prints
    `wrote N Markdown pages and llms-full.txt` (the deploy runs it, and a
    failure there blocks the deploy);
  - `_site/pubs.json`, `_site/news.json` and `_site/search.json` parse as
    JSON, and the `application/ld+json` block in `_site/pubs.html` parses;
  - the pages you touched look right in light and dark mode, and at phone
    width (about 375px);
  - the browser console shows no security-policy errors.

## Deploy

- `.github/workflows/pages.yml` runs on every push to `main` (and by hand):
  Ruby 3.3, `bundle exec jekyll build` with `JEKYLL_ENV=production`, Python
  3.12, `_scripts/agent_markdown.py _site`, then upload and deploy to Pages.
- Pages is set to deploy from GitHub Actions, and the `github-pages`
  environment only accepts deployments from `main`. If the default branch is
  ever renamed, update the workflow trigger, the environment's branch policy
  and the Pages settings together.
- Commit or push only when the user asks; a push to `main` is a release.

## Rules that are easy to break

- **Security policy.** `_includes/head.html` sets a Content-Security-Policy
  in a `<meta>` tag (Pages cannot set headers). It allows scripts and styles
  only from this site, Google Fonts and Cloudflare's analytics beacon.
  - No inline `<script>` code, `onclick=` attributes or `style=` attributes:
    they are blocked. Put code in `assets/js/` and styles in `site.css`.
  - `<script type="application/ld+json">` data blocks are fine (they don't
    execute).
  - A new third-party script, font, image host or API needs the policy
    updated, and should be avoided where possible.
- **Contact details** are deliberately not in plain HTML. The footer stores
  the email as `data-user`/`data-domain` and the phone in `data-phone`;
  `site.js` assembles them. Keep it that way.
- **Progressive enhancement.** Every page must work without JavaScript.
  Elements that need JS (filters, BibTeX buttons, search, theme toggle) start
  `hidden` and `site.js` reveals them.
- **Styling.** Use the existing custom properties (`--ink`, `--accent`,
  `--rule`, `--f-display`, …) rather than raw colours, and check dark mode.
  Fonts: Bricolage Grotesque (display), Source Serif 4 (body), JetBrains Mono.
- **Hero graph** (`graph.js`) reads its colours from CSS properties and
  listens for the `themechange` event. It respects reduced motion with a still
  frame. Its `aria-label` in `index.html` describes the animation; update it
  if the animation's story changes.

## Agent-facing files

| File | How it stays current |
| --- | --- |
| `index.md`, `research.md`, `pubs.md`, `news.md`, `students.md`, `llms-full.txt` | Written on every deploy by `_scripts/agent_markdown.py` from the built HTML |
| `pubs.json`, `news.json` | Liquid, from `_data/` |
| Publication structured data (`ItemList` of `ScholarlyArticle` in `pubs.html`) | Liquid, from `_data/pubs.yml` |
| Homepage Person data (`@id` `https://yazan.boshmaf.com/#me`) | Liquid in `_includes/head.html`, from `_config.yml` |
| `<link rel="alternate" type="text/markdown">` on each page | `_includes/head.html` |
| WebMCP tools (`search_publications`, `get_bibtex`, `list_news`, `get_contact`) | `webmcp.js` fetches `pubs.json` and `news.json` at run time; BibTeX comes from `window.__bibtex` in `site.js` |
| `llms.txt` | Liquid. Links and the paper count update themselves; the summary paragraph is hand-written |
| `robots.txt` | Fixed text: allows all crawlers, `Content-Signal: search=yes, ai-input=yes, ai-train=no`, sitemap link |

Hand-maintained spots:

- **Adding a page:** add it to `nav` in `_config.yml`, to `PAGES` in
  `_scripts/agent_markdown.py`, and to the "Pages" list in `llms.txt`.
- **Changing page markup:** `agent_markdown.py` reshapes specific markup
  before converting (`li.pub` with `.authors` and `.meta`, `li.year`,
  `.arc li` with exactly three children, `a.sys` with an `h3`, `.tags`,
  `time`, `a.cite`, `figure.graph-card`, `aside.toc`). If you change those
  structures, update the script and rerun it, or the deploy fails.
- **Research statement sections:** `search.json` lists the `research.html`
  section titles and anchors (`#s1`–`#s5`) by hand, and so does the
  table of contents at the end of `research.html`. Keep both in sync with the
  headings. The reference list in `research.html` is separate from
  `pubs.yml`.
- **New research focus or role:** update the summary in `llms.txt`, the
  `description` in `_config.yml`, the homepage hero and `knowsAbout` in the
  Person data in `_includes/head.html`.

## Cloudflare

Configured in the Cloudflare dashboard for the `boshmaf.com` zone, not in this
repo. All three rules match only `http.host eq "yazan.boshmaf.com"`.

1. URL Rewrite Rule "Markdown for agents (pages)": when the `Accept` header
   contains `text/markdown` and the path ends in `.html`, rewrite the path
   with `wildcard_replace(http.request.uri.path, "/*.html", "/${1}.md")`.
2. URL Rewrite Rule "Markdown for agents (homepage)": same `Accept` test,
   path `/`, rewrite to `/index.md`.
3. Response Header Transform Rule "Agent discovery headers": set
   `Link: </llms.txt>; rel="describedby"; type="text/plain", </sitemap.xml>; rel="sitemap"; type="application/xml"`
   and add `Vary: Accept`.

Cloudflare Web Analytics is also on; its beacon is why the security policy
allows `static.cloudflareinsights.com` and `cloudflareinsights.com`. A
redirect rule sends `boshmaf.com` to `yazan.boshmaf.com`.

To check from a shell:
`curl -H 'Accept: text/markdown' https://yazan.boshmaf.com/research.html`
should return Markdown, and `curl -sI https://yazan.boshmaf.com/` should show
the `Link` header. https://isitagentready.com scores the whole setup (level 3,
"Agent-Readable", as of Nov 2026; the remaining checks are for APIs and
services the site doesn't have).

  already uses it.
